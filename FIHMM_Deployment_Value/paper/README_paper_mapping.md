# Manuscript object -> code path

Every numbered object in the article, and the command that regenerates it.

## Where the data comes from

Every entry below reads from `data/` and nothing else. Table 1 and the L0-L2
regressions use `data/derived/panel_analysis.parquet` (577,245 rows); the
density comparisons use `data/derived/analysis_dataset.parquet`; Level 5 uses
`data/derived/backtest_metrics.csv`; the hazard rows use
`data/derived/hazard_predictions.parquet`.

## The survivor's five boundary conditions

Section "Characterization of the Surviving Predictor". Each is checked by
`reproduction/verify_results.py::verify_survivor`.

| # | Condition | Where |
|---|---|---|
| 1 | Baseline sensitivity (-2.22 vs -1.29 bare) | `baseline_comparison.survivor_vs_bare_baseline` |
| 2 | Search multiplicity (0.0095 -> 0.038 Holm, 0.052 common) | `analysis/multiple_testing.holm` |
| 3 | Sequential search cost | `analysis/multiple_testing.sequential_search_note` |
| 4 | Metric centrality (CRPS is centre-weighted) | `src/models/density.tail_weighted_crps` |
| 5 | Nested-model inference (bootstrap 0.033; Clark-West +1.27, p=0.10) | `analysis/statistical_tests.clark_west` |

Condition 5 is the one most likely to be misread as a bug. The Clark-West
adjustment **does not clear its bar**, and that is reported rather than
resolved: the estimation scheme is expanding-window, so the Giacomini-White
finite-window argument that would license the unadjusted Diebold-Mariano
comparison does not apply. The survivor is offered as a demonstrated
possibility under its pre-registered gate, not a confirmed general effect.
